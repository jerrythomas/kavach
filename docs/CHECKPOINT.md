- **Deploy repaired — it had been dead 15 days.** Two stacked faults, both now
  fixed and confirmed by a live fetch of the deployed manifest:
  1. bun drift. The repo declared `bun@1.3.10`, Cloudflare honoured it, but
     bun.lock was regenerated by a local 1.3.14 (dep upgrade + release-prep),
     so `--frozen-lockfile` aborted. CI hid this because every workflow asked
     for `bun-version: latest`, which _is_ 1.3.14. All four now read
     `bun-version-file: package.json`; that file is the single source of truth.
  2. `sites/*/uno.config.js` imports `kavach`, whose exports resolve to `dist/`
     — gitignored, so absent on a clean clone. `prebuild`/`predev` now run
     `build:all` first, making the site build self-sufficient.

- **Security:** secret scanning, push protection, Dependabot alerts and security
  updates **enabled** (were all off). `non_provider_patterns` and
  `validity_checks` accept the API call but need a paid Secret Protection
  licence. Added `security.yml` — audit gated at high, dependency-review on PRs,
  zizmor (SARIF, 0 alerts). `bun audit`: 7 vulns, **0 high/critical**; five are
  transitive via `firebase-tools`, a devDep of the private demo site.

- **Dependabot scoped to github-actions only.** Its `npm_and_yarn` ecosystem

Process notes, both learned the hard way:

- bumpp's `all: true` is `git add -A` and stages UNTRACKED files — v1.2.0 swept
  a stray epub into the release commit. Verify a clean tree before releasing.
- npm dependency currency is manual: `bun run upgrade:all`, then the full gate.
  Note `bun update --latest` does NOT rewrite workspace manifests that pin exact
  versions — the three sites needed editing by hand.
- Cloudflare's build command must be `bun run build` with root `sites/learn`.
  `build:all` alone builds the 14 packages but never runs `vite build`, so
  wrangler finds no `_worker.js`.
